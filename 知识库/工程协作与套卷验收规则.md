# 工程协作与套卷验收规则

本规则适用于本工程后续的建议、修改和套卷交付。目标是让决策有据可查，让每套卷的成品与检查记录对应，避免仅凭口头结论或旧报告交付。

## 1. 知识库是唯一的 Markdown 归档位置

- 原“规范”目录改名为“知识库”。项目中新建或保留的 `.md` 文件均放在此目录或其子目录，不在工程根目录、`模式题`或`.work`另放 Markdown。
- 命题方法写入相应规范；单套卷的索引和检查记录写入`知识库/套卷索引/`。Word 成品仍放`模式题/`，源稿和程序报告仍放对应的独立工作目录。
- 移动文件后检查所有相对链接、复制用的绝对路径和脚本输出路径。

## 2. 建议与修改意见必须落地

- 收到新的建议、修改意见或发现可重复的问题时，先在[建议与变更记录](./建议与变更记录.md)记录来源、具体内容、处理决定和验证结果；不能只在对话中口头说明。
- 可复用的结论应进一步写成可执行、可检查、有适用边界的规则，更新固定模板或质检规范；只属于某套卷的情况写进该卷检查记录，不误升为通用规则。
- 尚未核实或尚未处理的意见标为“待确认／待处理”，不得写成已解决。修改规则后核对相关脚本与文档是否同步。

## 3. 每套卷同时生成 Markdown 索引

- 每次生成 Word 套卷时，同时建立同名 Markdown 记录，放在`知识库/套卷索引/`；记录至少包含卷名、Word 路径、源稿或工作目录、题量结构、版本、检查状态和需要人工确认的事项。
- Markdown 是索引及检查记录，不复制完整题干、题图和解析；题目正文以该卷的单一数据源和 Word 成品为准。
- 新卷应有独立文件名与工作目录，不覆盖已有卷。若用户另有格式要求，先确认再调整。

## 4. 生成后再复核一次

- Word 与 Markdown 都生成后，必须对最终版本重新执行内容、答案、编号、图片及文件一致性检查；实际导出 PDF，逐页检查渲染图，不沿用旧版本的预览或报告。
- 检查结果写回该卷 Markdown：程序检查的范围和结论、渲染页数、人工逐页检查状态、独立教师审题／试测状态、发现的问题和修复后回归结果。程序通过不能代替人工视觉检查或独立审题。
- 任一成品内容或排版再次修改，原检查结论立即失效；重新生成预览并复核后才能标记为可交付。无法完成的环节须写明原因和待办。

## 5. 有疑问先提问

- 对需求、题目结论、资料真实性、输出格式、覆盖旧文件、目录位置或验收标准有疑问或不确定时，先向用户提出具体问题，再做会受答案影响的决定。
- 提问时说明当前已知事实、待选方案及默认建议；用户未答复前，仅继续不依赖该答案的安全工作，不把猜测写成定论或已获批准的规则。
- 用户的答复和由此形成的决定记入[建议与变更记录](./建议与变更记录.md)，必要时同步更新固定模板。
